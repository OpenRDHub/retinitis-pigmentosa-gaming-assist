# Full-Screen Map Awareness for RP Gamers · 视力障碍玩家全屏地图识别工具

> 「罕见·无界」黑客松 · 赛题6 · 遗传性视网膜色素变性 + 游戏辅助工具（赛题序号 08）
> 依据《为视力障碍玩家打造识别全屏地图的工具 产品需求书 V1.0》（2026-10-01）编写 · 需求发起人：Hero（RP 患者，中心残余视力仅 0.01）· [OpenRD 罕见病开源社区（Khub）](https://github.com/OpenRDHub)

做一个**「小地图哨兵」**：外挂式只读屏幕，把视野之外的战局翻译成**空间音频与触觉反馈**——不遮挡仅存视野、不替代玩家思考。

**核心结论（TL;DR）**：

1. 患者不是「看不见」，是**「看得太少」**——中心残余视力仅 0.01、管状视野，要补的是周边信息，不是放大画面
2. **外挂式只读屏幕**——不读内存、不注入 DLL、不模拟点击，只做「截屏→理解→提示」
3. **反馈走耳朵和手**——空间音频+震动；铁律是任何 UI 都不进仅存的中心视野
4. **极低延迟是硬指标**——报点慢 0.5 秒玩家已经「成盒」，端侧推理需压到几十毫秒
5. **信息做减法不做加法**——语音只说 Top1 威胁，团战自动降级为极简模式，其余静默

## 🧭 一、疾病背景

视网膜色素变性（Retinitis Pigmentosa，RP）是遗传性、进行性的视网膜退行性疾病，最常见的遗传性致盲眼病之一：全球患病率约 1/4000，中国患者超过 100 万；高度遗传异质性（已发现超过 100 个致病基因）；多数儿童期/青少年期发病。致病机理为感光细胞进行性凋亡（视杆细胞首先受累→夜盲与视野缩窄；视锥细胞逐渐受损→中心视力下降）。目前无根治方法，基因治疗（Luxturna 等）尚在临床研究阶段。

**核心症状**：夜盲（最典型早期症状）、进行性视野缩小（管状视野，「通过一根吸管在看世界」）、中心视力受损；伴畏光、色觉异常、对比度敏感度下降、闪光感。

**对玩家「视野」的具体影响**：只能看到屏幕中心一小块，屏幕边缘的敌人靠近、队友信号、技能特效完全无法察觉；昏暗场景（洞穴/夜晚地图）操作困难加剧；快速移动目标难以追踪；放大镜/读屏软件要么破坏沉浸感、要么跟不上实时操作。

## 👤 二、用户画像与典型场景

**Hero 本人**：RP 患者，视野严重缺失，中心残余视力仅 0.01——但仍是一名希望继续游玩**主流商业游戏**的游戏爱好者。

**核心需求**：实时读取并「翻译」玩家视野之外的屏幕地图信息（尤其周边关键动态），以**语音播报、震动提示、边缘光效**等可感知方式反馈。

| 场景 | 游戏 | 类型 | 挑战 |
|---|---|---|---|
| 一 | 王者荣耀 | MOBA | 最典型：只能感知角色周围极有限画面，屏幕边缘的战场完全不知道 |
| 二 | 和平精英 | FPS/吃鸡 | 全局态势感知要求最高，听声辨位与视野缺一不可，RP 玩家两方面都受限 |
| 三 | 开心消消乐 | 休闲益智 | 看似简单，同样依赖全局视野规划策略 |
| 四 | 原神 | 开放世界 RPG | 信息密度极高、地图广袤、元素繁多 |

## 📉 三、已尝试方案及失败原因（发起者真实经验）

1. **大屏幕/平板**——反而更糟：画面元素等比放大，「用一根吸管看一个更大的世界」，盲区更大。**患者需要的不是「看得更清楚」，而是「知道周围发生了什么」**
2. **助盲音频游戏**——玩法单薄；最致命的是无法与朋友开黑社交，游戏核心社交属性被剥夺，反而加剧孤独感。**「无障碍」不等于「好玩」，更不等于「能和朋友一起玩」**
3. **调整游戏内设置**——只能优化「看得怎么样」，无法解决「看得到哪里」
4. **屏幕放大镜/辅助软件**——进一步压缩视野，全局感知类游戏里几乎「自废双眼」，且画面移动易眩晕

## ⚖️ 四、设计约束（七条铁律）

> 任何一条破了，方案就不成立。七条共同指向一句话：**补信息，不添乱；做队友，不做代打。**

| # | 铁律 | 说明 |
|---|---|---|
| 01 | 不遮挡视野 | 任何 UI/弹窗不占仅存的中心视野；提示音、震动、边缘光效、骨传导等不依赖视力的交互可能更有效 |
| 02 | 实时性极致 | 报点慢 0.5 秒玩家已「成盒」；方案必须极低延迟 |
| 03 | 提示不代思考 | 提供「左侧有敌人」式的辅助，而不是「自动开火」式的替代决策 |
| 04 | 外挂式兼容 | 通用外挂式工具，从屏幕画面实时提取信息，不依赖特定游戏引擎或 API |
| 05 | 高度可定制 | 残余视力/视野/游戏偏好因人而异；提示频率、方式（语音/震动/光效）、详略、音色音量均可调 |
| 06 | 隐私与尊严 | 玩家不希望因使用辅助工具被歧视——做成「谁都想要的外挂」，只是它助力的是真正的玩家 |
| 07 | 守伦理边界 | 遵守游戏厂商服务条款；聚焦「读取、理解、翻译呈现」而非「自动操作」，避免被判定为作弊 |

## 🏗 五、总体架构：三层流水线

```
感知层（读懂屏幕）→ 调度层（筛出威胁）→ 呈现层（交给耳朵和手）
```

**① 感知层**：Graphics Capture（PC）/ MediaProjection（Android）截屏；小地图定位与标定（模板匹配/Hough 圆/语义分割，支持首次手动框选后记忆）；YOLOv11/v12 检测敌方图标；VLM 生成语义描述。输出不是精确坐标，而是「左前方草丛有人靠近」。

**② 调度层**：聚合成「威胁事件」；**优先级 = 威胁度 × 紧迫度 ÷ 距离**；合并/聚类/冷却去重（同侧同类合并成「左侧两人」；同一目标 1.5 秒内不重复；只在状态变化时才报）；团战检测与自动降级。

**③ 呈现层**：空间音频（HRTF，最多 3 声源；方位用声音方向编码，距离用音量编码，越紧急脉冲节奏越快）；左右马达触觉编码（左右表方位、强度表距离、短震「危险」长震「即将命中」，每秒最多 2 次防麻木）；语音只播 Top1、2 字短提示。三通道分工：**语音→Top1；空间音→Top3；触觉→Top2**。

**分层提示逐级介入**：一级背景态势（环境音/微震动）→ 二级威胁变化（空间音+触觉）→ 三级紧急事件（短语音打断）→ 四级主动查询（按键才报详细战局）。

**团战期间只做减法**：检测到团战自动关闭所有视觉光效、语音只播最紧急 1 条且只用 2 字词（「左闪」「退」）、空间音最多 3 声源、触觉只对「即将命中自己的技能」短震，其余静默——团战只告诉玩家「现在必须知道的那一件事」，并提前 0.3–0.5 秒预测报点。

## 🚀 六、最小可行原型（MVP）

先做「小地图哨兵」，不做全屏理解：

1. 用户手动框选小地图区域，标定一次后记忆
2. YOLO 检测敌方图标，模板匹配找玩家箭头
3. 输出相对极坐标，归一化为方位与距离等级
4. 事件融合引擎做优先级、合并与冷却
5. 输出空间音频+左右震动，语音只播 Top1
6. 用户可调提示频率与方式

技术栈：OpenCV + YOLO + 音频 API（NCNN/ONNX Runtime 端侧推理 <10ms、显存 <1GB），配蓝牙骨传导耳机（保留环境音，适合 FPS 听声辨位）。小地图跑稳后，再扩展全屏技能特效与队友信号。

**非功能需求**：端侧推理几十毫秒级；任何 UI 不占中心视野；显存 <1GB 普通设备可跑；提示全面可定制；只读不写、不模拟点击、不碰 root/Shizuku 输入注入；跨游戏通用（靠读屏画面）。
